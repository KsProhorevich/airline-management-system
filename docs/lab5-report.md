# Лабораторная работа №5. REST API

Архитектура лабораторной №5 сохранена: Minimal APIs, EF Core SQLite, JWT, роли `Dispatcher` и `Passenger`, репозитории, `IUnitOfWork`, DTO, проверка данных, `ProblemDetails`, пагинация, фильтры, сортировка, Swagger и CORS. Подробный разбор исходного API остаётся в `README.md` и `docs/lab5-audit.md`.

## Что не менялось в контракте

- Пассажир бронирует только себя: `passengerId` из тела игнорируется, владелец берётся из `sub`.
- Диспетчер обязан передать `passengerId` пользователя с ролью `Passenger`.
- Отмена ставит `Cancelled` и возвращает места, строка не удаляется.
- Одна активная бронь пассажира на рейс. Мест в одной брони от 1 до 9.
- Неверный пароль и неизвестный email дают один и тот же `401`.
- Ключ JWT и пароли в репозиторий не записываются. Пустой `Jwt:SigningKey` в `appsettings.json` намеренный: процесс без ключа не стартует.

## Добавленные маршруты

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| GET | `/api/aircraft` | анонимно | Страница судов |
| GET | `/api/aircraft/{id}` | анонимно | Карточка судна |
| POST | `/api/aircraft` | Dispatcher | Создать судно |
| PUT | `/api/aircraft/{id}` | Dispatcher | Изменить судно |
| DELETE | `/api/aircraft/{id}` | Dispatcher | Удалить судно, если нет рейсов |
| GET | `/api/passengers` | Dispatcher | Имя, email и дата создания. Без пароля и токена |
| GET | `/api/demo/ado/flights-by-status` | Dispatcher | Подсчёт рейсов параметризованным SQL |
| GET | `/health` | анонимно | Проверка живости, скрыта из Swagger |

`FlightResponse` дополнительно отдаёт `aircraftId`, `aircraftRegistration`, `aircraftModel`. Старые поля рейса на месте. `GET /api/flights` принимает необязательный `aircraftId`.

Создание рейса без `aircraftId` подставляет резервное судно. Это сохраняет прежние клиенты и тесты.

## Ошибки

Новые операции используют те же исключения и `ProblemDetails`: `400` для проверки, `401` без токена, `403` для чужой роли, `404` если записи нет, `409` для уникального номера, занятого судна и запрета удаления.

## Проверено автоматически

Прежние тесты `WebApplicationFactory` входят в общий прогон `dotnet test`: 29 интеграционных случаев на временном SQLite, включая 26 прежних и 3 новых для судов, пассажиров и ADO.NET-эндпоинта. Модульные тесты сервиса бронирования в это число не входят.
