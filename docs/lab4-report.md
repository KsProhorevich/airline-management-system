Вариант 10, система управления авиакомпанией. Основа — существующий `AirlineApi`. Каталог `lab4` содержит загрузчик файлов без базы авиакомпании, поэтому схема не сливалась с чужим проектом.

## Модель

Пассажир — это уже существующий `User` с ролью `Passenger`. Отдельная сущность пассажира не добавлялась: у пользователя уже есть коллекция `Bookings`. Искусственная связь один-к-одному не вводилась.

| Сущность | Связь |
|---|---|
| `Aircraft` | один ко многим `Flight` |
| `User` (пассажир) | один ко многим `Booking` |
| `Flight` | один ко многим `Booking` |
| Пассажир и рейс | многие ко многим через `Booking` |

Удаление судна и рейса — `Restrict`. Судно с рейсами и резервное судно `RA-0001` не удаляются (`409`). Рейс с любой бронью, включая отменённую, по-прежнему не удаляется.

Аннотации: `[Table]`, `[Key]`, `[Required]`, `[MaxLength]`, `[Column("Registration")]`, `[ForeignKey]`, `[Range]`. Fluent API в `OnModelCreating`: уникальный регистрационный номер, проверка `CK_Aircraft_SeatCapacity`, внешний ключ `AircraftId`.

`aircraftId` при создании и изменении рейса необязателен. Если его нет, берётся резервное судно `22222222-2222-2222-2222-222222222201`, вместимость 500. Число мест рейса не может превысить вместимость судна. Правила мест, отмены, повторной активной брони и `Version` не переносились в массовые операции.

## ADO.NET и EF Core

`AdoNetDemoService` открывает отдельный `SqliteConnection` по строке подключения контекста. Это тот же файл SQLite, не вторая база.

- Параметризованный `SELECT` считает рейсы по статусу через `SqliteParameter` и `SqliteDataReader`. Значение не склеивается со строкой SQL.
- `RenameRegistrationAsync` выполняет `UPDATE` в `SqliteTransaction`. Успех завершается `Commit`. Исключение до фиксации вызывает `Rollback`. Соединение, команда, читатель и транзакция освобождаются через `await using`.
- HTTP показывает только чтение: `GET /api/demo/ado/flights-by-status` для роли `Dispatcher`. Произвольный SQL с клиента не принимается. Откат транзакции проверяет тест, а не публичный эндпоинт.

EF Core используется для обычных репозиториев: Code First, `Add`, `Find` в демонстрации, `Remove`, LINQ, `Include` самолёта у рейса, `AsNoTracking` у списков. `EfCoreFeatureDemo` в тесте показывает состояния `Added`, `Unchanged`, `Modified`, затем `ExecuteUpdate` и `ExecuteDelete` на временной строке судна. Эти массовые операции не стоят на пути бронирования.

Списки рейсов загружают судно одним `Include` после `Skip`/`Take`, а не отдельным запросом на каждую строку.

## Миграции

Прежняя миграция `20261017203737_InitialCreate` не переписывалась. Добавлена `20261017205726_AddAircraft`: сначала таблица `Aircraft` и резервная строка, затем обязательный `AircraftId` со значением резервного судна, затем внешний ключ. Так существующие рейсы не остаются с пустым ключом.

Фактически выполнено из каталога `lab5`:

```text
dotnet ef migrations add AddAircraft --project AirlineApi/AirlineApi.csproj --startup-project AirlineApi/AirlineApi.csproj --output-dir Data/Migrations
dotnet ef migrations list --project AirlineApi/AirlineApi.csproj --startup-project AirlineApi/AirlineApi.csproj
dotnet ef database update --project AirlineApi/AirlineApi.csproj --startup-project AirlineApi/AirlineApi.csproj
```

`migrations list` показал обе миграции как Pending, потому что файла `AirlineApi/App_Data/airline.db` ещё не было. `database update` создал этот файл и применил обе миграции. Существующую базу удалять было нечего. `dotnet ef migrations remove` не запускался: команда удалила бы только что добавленную миграцию.

Проектная фабрика дизайна указывает на `App_Data/airline.db`. Учебные рейсы записывает не миграция, а `DatabaseInitializer` при старте приложения, если таблица рейсов пуста.

## Проверено автоматически

- Параметризованный запрос не принимает текст, похожий на внедрение SQL, и считает только запрошенный статус.
- Откат оставляет регистрационный номер прежним; успешная транзакция его меняет.
- Демонстрация EF Core проходит состояния и удаляет свою временную строку.
- Свежая тестовая база применяет миграции через `MigrateAsync`.
